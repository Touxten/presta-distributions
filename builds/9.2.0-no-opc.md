## Méthode

Dans un nouveau dossier de travail, avec PHP 8.3, Composer et Node.js 22 :

```sh
git clone --depth 1 --branch 9.2.0 https://github.com/PrestaShop/PrestaShop.git source
cd source
composer remove prestashop/ps_onepagecheckout --no-install --no-scripts --no-interaction --minimal-changes
git add composer.json composer.lock
git commit -m 'Build 9.2.0 without ps_onepagecheckout'
php tools/build/CreateRelease.php --version=9.2.0 --destination-dir=/chemin/absolu/outputs
```

Le commit local est nécessaire : l’outil officiel exporte `git archive HEAD`,
pas les modifications non committées. Utiliser un répertoire temporaire vide sur
un système de fichiers compatible avec les liens symboliques.

Sur la machine de compilation, les cinq tâches d’assets de `make assets` sont
exécutées séquentiellement via `tools/assets/build.sh` (admin-default,
admin-new-theme, front-core, front-classic, front-hummingbird). Le nombre de
workers Node est limité à deux pour maîtriser la mémoire ; aucun script source
de PrestaShop n’est modifié.

Le ZIP et le XML sont produits par l’outil officiel. Seuls leurs noms sont ensuite
changés en `prestashop_9.2.0-no-opc.zip` et `prestashop_9.2.0-no-opc.xml` afin de
distinguer la variante ; la version interne reste `9.2.0`.

Le script `scripts/verify-no-opc.php` contrôle le ZIP final, l’intégralité des
sommes XML et l’absence du module ainsi que de ses références d’autoload.
Installation et mise à jour complètes restent à valider séparément.

(avec avertissements amont). Contrôle final : 26 160 fichiers vérifiés dans le ZIP
